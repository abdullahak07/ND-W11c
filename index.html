Tiny devices create a giant attack surface.

IoT is difficult to secure because devices are numerous, resource-constrained, physically exposed, built by many vendors and often deployed faster than security planning can keep up.

MINISEC + LIGHTWEIGHT SECURITY

How do you secure a tiny sensor with almost no spare battery or memory?

MiniSec is a lightweight link-layer security module for TinyOS sensor networks. Its challenge is to deliver real confidentiality, authentication and replay protection with very low overhead.

GAME 7 · STOP THE REPLAY ATTACK

MiniSec-U has already accepted counter 42. What should the receiver do with each next packet?

Accept counters greater than the last valid one. Reject equal or smaller counters.
MiniSec-U

Unicast

Synchronized counter per sender. Great for one-to-one communication.

Receiver rejects equal or smaller counters.
MiniSec-B

Broadcast

Timing epochs + bloom filter avoid huge per-sender memory cost.

Designed for many senders / receivers.
GAME 8 · PICK THE MODE

One sensor sends privately to one gateway. Which mode?

SKIPJACK

Fast + small, but dated

80-bit key; historically attractive for constrained systems because code, memory and computation were efficient. The lecture notes that 80 bits is now generally inadequate and newer lightweight algorithms are preferable going forward.

OCB

One-pass authenticated encryption

Combines encryption and authentication efficiently. It is designed to minimize block-cipher calls and suits stringent sensor-node energy constraints.
